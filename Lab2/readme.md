## 1. Төслийн зорилго

Нийтийн дугуй түрээсийн систем нь хотын иргэд, оюутнууд, жуулчид болон бусад хэрэглэгчдэд нийтийн зориулалттай дугуйг хурдан, хялбар түрээслэх боломж олгох систем юм.

Системийн үндсэн зорилго нь хэрэглэгчид:

- Ойролцоох дугуйн зогсоолыг олох
- Сул дугуйн мэдээлэл харах
- QR код ашиглан дугуй түрээслэх
- Түрээсийн хугацаа болон төлбөрийг хянах
- Дугуй буцаах
- Цахимаар төлбөр төлөх
- Түрээсийн түүхээ харах

боломжийг нэг системээр олгоход оршино.

---

## 2. Шийдвэрлэх асуудал

Хот дотор богино зайд зорчих үед автомашин болон нийтийн тээвэр ашиглах нь зарим тохиолдолд цаг хугацаа их шаарддаг.

Мөн дараах асуудлууд тулгардаг:

- Замын түгжрэл
- Авто зогсоолын хүрэлцээ
- Богино зайд зорчиход тохиромжтой тээврийн хэрэгслийн хэрэгцээ
- Нийтийн тээврээс хамааралтай байдал
- Түргэн, хялбар зорчих боломжийн дутагдал

Нийтийн дугуй түрээсийн систем нь хэрэглэгчдэд богино зайд хурдан зорчих өөр сонголт бий болгож, нийтийн дугуйн ашиглалтыг системтэй удирдах боломж олгоно.

## 6.2 INVEST зарчмын тайлбар

**Бие даасан:**  
Хэрэглэгчийн шаардлага бүр нэг тодорхой хэрэгцээг илэрхийлж байгаа.

**Хэлэлцэгдэх боломжтой:**  
Шаардлагууд нь ямар технологи ашиглахыг нарийвчлан заагаагүй тул хэрэгжүүлэх арга нь хэлэлцэгдэх боломжтой.

**Үнэ цэнтэй:**  
Шаардлага бүр хэрэглэгч эсвэл системийн операторт тодорхой ашиг, үнэ цэнэ өгнө.

**Үнэлэгдэх боломжтой:**  
Шаардлагуудын хамрах хүрээ тодорхой тул хөгжүүлэлтийн ажлын хэмжээг үнэлэх боломжтой.

**Жижиг:**  
Нэг User Story-д бүх системийг багтаагаагүй бөгөөд нэг тодорхой үйлдэлд төвлөрсөн.

**Туршигдах боломжтой:**  
Шаардлага бүрийн үр дүнг тестээр шалгах боломжтой.

# 11. Дүгнэлт

Энэхүү лабораторийн ажлаар **Нийтийн дугуй түрээсийн систем** төслийн зорилго, хэрэглэгчид, хамрах хүрээ болон үндсэн функцуудыг тодорхойлов.

Хэрэглэгчдийн хэрэгцээнд тулгуурлан нийт **15 User Story** боловсруулж, бүтээгдэхүүний Backlog үүсгэн эрэмбийг тодорхойлов.

User Story бүрийг **Independent, Negotiable, Valuable, Estimable, Small, Testable буюу INVEST** зарчмын дагуу шалгасан.

Мөн User Story бүрт хүлээн авах шалгуур тодорхойлсноор хөгжүүлэлт болон тестийн үед тухайн шаардлага биелсэн эсэхийг шалгах боломжтой болсон.

Ингэснээр нийтийн дугуй түрээсийн системийн үндсэн шаардлага, хэрэглэгчийн хэрэгцээ болон цаашдын хөгжүүлэлтийн ажлын суурь Backlog бүрдсэн.
