## Загварын шийдвэр

- Нэвтрэлт бол QR түрээсийн урьдчилсан нөхцөл. Түрээслэх бүрд login ажиллагааг дахин гүйцэтгэх
  гэсэн утгатай `include` холбоос ашиглаагүй.
- UserRole-оор CUSTOMER, OPERATOR, MAINTENANCE эрхийг ялгасан. Operator-ийг заавал User-ийн
  subclass болгох бизнесийн шаардлага байхгүй тул зохиомол inheritance нэмээгүй.
- Түрээстэй дугуй одоогийн зогсоолгүй байж болно: Station талын multiplicity **0..1**.
- Нэг Rental-д төлбөр үүсээгүй байж болно: Payment тал **0..1**; нэг Payment яг нэг Rental-д хамаарна.
- Төлбөрийг Decimal, нууц үгийг passwordHash хэлбэрээр загварчилсан.
- Давхар түрээсээс хамгаалах логик нь нэг transaction дотор байна. Бодит IoT түгжээний
  баталгаажуулалт/compensation нь дараагийн нарийвчилсан загварын хүрээнд.

## Архитектурын үндэслэл

Гурван гишүүнтэй баг UI, бизнес логик, өгөгдлийн ажлыг тусгаарлан хөгжүүлэхэд Layered архитектур тохиромжтой.
Мобайл болон операторын вэб ижил service-ийг ашиглах тул түрээс, төлбөрийн дүрэм давхардахгүй.
Repository интерфейс ашигласнаар өгөгдлийн сан эсвэл UI өөрчлөгдөхөд бусад давхаргын өөрчлөлт багасна.
Төлбөрийн гадаад үйлчилгээг adapter-аар тусгаарлах нь дараагийн өргөтгөл, тест, засвар үйлчилгээг хялбарчилна.
