# Code Review — техникийн санал ба бодит хүний review-ийн төлөв

**Техникийн шалгалт:** автомат туслах, нэг локал Git зохиогч.
**GitHub pair review:** хийгдээгүй; бичих API нь 403 алдаатай.
Доорх нь үнэхээр шалгасан кодод өгсөн 4 техникийн санал. Хоёр өөр хүн PR дээр comment
бичсэн, эсвэл хосоор ажилласан гэж тайлагнаагүй.

## Feature A — `feature/greeting-name`

Анхны commit: `5fb9c0c`.

1. **A1 — Хоосон нэрийн үр дүн:** `greeting()` нь `Сайн уу, !` гэсэн эвгүй текст үүсгэнэ.
   `name.strip()` ашиглаж, цэвэр нэр хоосон бол нэртэй угтварыг бүхэлд нь алгасах саналтай.
   Хоосон, зөвхөн зай, Монгол нэр гэсэн нөхцөлөөр үр дүнг шалгана.
2. **A2 — CLI-д нэр дамжуулах:** `__main__` хэсэг үргэлж `greeting()` дуудсан тул
   шинэ `name` боломж командын мөрөөс ашиглагдахгүй. Нэмэлт аргументуудыг нийлүүлж
   функцэд дамжуулах; импортын үед хэвлэхгүй main guard-ийг хадгалах саналтай.

Эдгээрийг Feature A-ийн тусдаа `fix(lab6)` commit-д хэрэгжүүлсэн.

## Feature B — `feature/greeting-safety`

Анхны commit: `e386a3e`.

1. **B1 — Нийтийн интерфейсийг хадгалах:** `greeting(name)` аргумент байгаа ч функц
   нэрийг ашиглахгүй. Нэртэй угтварын ижил дүрмийг нэмснээр Feature A-тай нэгтгэх үед
   хэрэглэгчийн нэр алдагдахгүй; blank/trim нөхцөлийг мөн баримтална.
2. **B2 — Ашиглагдахгүй safety helper:** `safety_note()` нэмсэн боловч entry point дуудахгүй
   тул CLI хэрэглэгч аюулгүй байдлын зөвлөмжийг харахгүй. Main guard дотор тусад нь
   хэвлэж, импортын үед дуудахгүй байх саналтай.

Эдгээрийг Feature B-ийн тусдаа `fix(lab6)` commit-д хэрэгжүүлсэн.
Conflict шийдэхдээ Feature A-ийн төслийн нэр, CLI аргумент болон Feature B-ийн
аяллын уриа, safety_note()-ийг бүгдийг хадгалсан.

## Багийн 2 хүний GitHub review

Удирдамж нь **хоёр хүн нэг нэгнийхээ PR дээр тус бүр 2 бодит, ашигтай comment** бичихийг шаарддаг.
Энэ хэсгийг нөхөхөд өөр өөр GitHub аккаунттай багийн хоёр гишүүний оролцоо шаардлагатай.

өөр хүн хийсэн мэт хуулж, хийгдээгүй хамтын ажиллагааны нотолгоо болгон ашиглахгүй.
